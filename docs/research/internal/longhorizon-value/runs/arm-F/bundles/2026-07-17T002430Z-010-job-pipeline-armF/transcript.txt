## What was built

**`eaitl/pipeline.py`** — `run_job(text, fmt, target_schema, target_examples=None) -> dict` — composes the six ratified stages into one pure, deterministic state machine:

1. `introspect` → `introspect_source(text, fmt)` (full return)
2. `propose` → `propose_mappings(schema, target_schema, samples, target_examples)` → `{"ir": ...}`
3. `validate` → `validate_ir` first (non-empty → fails the stage with a code-and-location message via a private internal exception), then `validate_mappings(ir, target_schema)` → `{"warnings": ...}`
4. `confirm` → `confirm_mapping(ir)` → `{"version": <64-hex>}`
5. `compile` → `{"python": compile_python(ir), "typescript": compile_ts(ir)}` — both, always
6. `preview` → `run_preview(text, fmt, ir)` (full return)

A single try/except with a `current`-stage marker records each completed artifact and, on `IntrospectError`/`MatchError`/`MappingError`/validator-contradiction, returns `{status: "failed", failed_stage, error, stages}` holding **only the completed prefix**. Any other exception propagates. The only edit to an existing file is the `run_job` export in `eaitl/__init__.py`.
