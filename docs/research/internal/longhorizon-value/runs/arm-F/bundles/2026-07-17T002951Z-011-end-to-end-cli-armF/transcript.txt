## Key design points (matching the spec exactly)

- **Exit-code boundary**: usage errors funnel through a `_UsageError` exception → stderr + exit 2, with `run_job` never called. A custom `ArgumentParser.error` override converts argparse failures into the same path (so `main` returns an int, never raises `SystemExit`). `--out` is created **last** among pre-flight steps, so a bad input never leaves a stray directory.
- **Source read as raw text** even for `.json` — a truncated `.json` flows into the pipeline and fails at introspect (exit 1), not the CLI (exit 2). Only `target_schema`/`target_examples` are JSON-parsed by the CLI.
- **Byte-deterministic writes** to `--out` only: `transform.py`/`transform.mts` (byte-exact compiler output, `newline=""`), `job.json` always (`json.dumps(..., indent=2, sort_keys=True, ensure_ascii=False)` + `\n`).
- Paths printed as `<out>/…` joined with `/` exactly as given.
